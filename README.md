# 一起看 · Jellyfin VRC Relay

轻量、自托管的视频缓存中转与直播服务：支持 Jellyfin / B 站点播，以及 OBS 推流、RTSP TCP 直播，适用于兼容的 VRChat PC 世界播放器。

源站只需向中转服务器提供缺失的数据，多个观众复用云端缓存，减少 NAS 重复上传。同一片段并发回源会合并；已淘汰的片段、不同转码参数或失败重试仍可能再次回源，不保证整部视频永远只下载一次。

**项目只提供软件，不提供视频、公共中转节点、内容授权或运营资质。部署前请阅读下方的[合法使用与合规](#合法使用与合规)。**

## 项目缘起

这个项目起初是为了一个很具体的需求：把自己 NAS 上的视频放进 VRChat，和朋友一起看，还能像普通电影一样暂停和拖动进度。

直接把 Jellyfin 播放地址交给房间播放器，看起来已经能解决问题，但每位观众通常都会独立拉取一份视频。人越多，NAS 上传和内网穿透流量的压力就越大。如果手上还有一台出口带宽更充足的云服务器，就可以让它承担多人观看时的分发工作：NAS 把需要的数据传给云端，观众再从云端共享缓存中读取。

项目因此从一个简单的中转工具，逐步加入共享缓存、NAS 转码、字幕烧录、预载、动态限速及统一管理页面。它的意义是把家中有限的上传资源与云服务器的分发能力结合起来，让小范围共同观看更容易部署和维护，而不是让每增加一位观众都重复消耗一份 NAS 上传。

它适合有合法内容来源、需要把视频提供给少量已授权观众的自托管场景。云端仍需承担所有观众的出口流量，缓存也会占用磁盘；本项目减少的是重复回源，不会凭空增加总带宽，也不负责 VRChat 房间内的播放控制和进度同步。

## 为什么默认转成 H.264 / AAC？

开发过程中遇到过这样的情况：同一部视频在 VLC 中播放流畅，在 VRChat 世界播放器中却持续卡顿；改用 H.264 视频与 AAC 音频的素材后，播放恢复正常。这个现象说明不同播放器的解码与格式支持会影响体验，但仅凭这一组对比，不能把所有卡顿都归因于 HEVC。

**默认转码的目的是优先提高目标播放器的兼容性，并控制输出码率。** 视频文件能在 VLC 或 Jellyfin 网页播放，不代表它的编码、音轨和封装组合在房间播放器里也能顺利播放；Jellyfin 网页还可能已经自动选择了适合浏览器的转码输出。

- **H.264 视频**：作为本项目面向 PC 房间播放器的默认兼容方案，减少直接保留 HEVC 等源编码时遇到的问题。转码时还能设置分辨率和目标码率，让传输需求更容易匹配服务器带宽。
- **AAC 音频**：配合本项目的 HLS TS 分片输出，避免直接保留 FLAC 等不受当前输出链路支持的音轨；默认使用 AAC 立体声。
- **代价与选择**：重新编码会占用 NAS 的 CPU/GPU、增加起播等待，也可能损失画质或音质。源文件已经适合播放器时，可以关闭对应转码选项或使用原文件模式，没必要为了“统一格式”再编码一次。

视频重新编码可选择 **H.264 或 HEVC（H.265）**；默认仍为 H.264。HEVC 需要 NAS 和目标播放器支持，选择 HEVC 不保证解决 VRChat 卡顿。用户实测的 VRChat / AVPro 世界组合无法正常播放 HEVC，即使音频为 192 kbps AAC；默认仍保持 H.264。可在“设置 → 播放默认值”保存默认是否重新编码及默认视频编码；这些默认值只影响新链接，已有链接保持原输出。

转码在 **NAS 的 Jellyfin** 上执行，云服务器负责缓存和发送。H.264/AAC 也不是所有卡顿问题的通用解法：NAS 转码速度、网络抖动、码率、播放器缓冲及房间实现仍会影响结果。

## 为什么需要字幕烧录？

Jellyfin 网页中能看到字幕，不代表复制视频链接后，VRChat 房间播放器也会显示字幕。外挂字幕是独立文件，内封字幕也是独立轨道；Jellyfin 客户端可以自行读取和显示它们，而房间播放器只获取视频流时，不一定会获取这些字幕或支持相应格式。本项目当前的 HLS 输出不单独提供可切换的软字幕轨道。

**字幕烧录会让 NAS 上的 Jellyfin 把选中的字幕绘制到每一帧画面中，再编码输出。** 这样观众看到的视频本身就包含字幕，无需房间播放器额外支持外挂字幕。云服务器仍只负责缓存和分发，不承担字幕渲染或视频编码。

使用 Jellyfin HLS 模式时：

1. 先确保外挂字幕已被 NAS 上的 Jellyfin 正确识别并关联到影片。
2. 点击读取字幕列表；有字幕时页面默认选中第一条，请确认语言和版本，必要时改选或选择不烧录。
3. 勾选“是否重新编码”，在后面的列表选择 H.264 或 HEVC（H.265），再生成播放链接。选择字幕不会自动勾选或改动视频编码；未启用重新编码时会明确提示，需手动启用或选择不烧录字幕。
4. 按需预载后，把生成的链接交给房间播放器。预载不是烧录的必要条件，但可以提前完成开头部分的转码和缓存。

烧录也有代价：字幕成为画面的一部分后，同一个播放链接中不能再关闭字幕或切换语言；更改字幕需要重新生成链接，会使用不同的转码与缓存，已有链接不会随之改变。字幕渲染与视频编码会增加 NAS 负载和起播等待，字体是否齐全、ASS 样式和复杂特效的呈现还取决于 NAS 上的 Jellyfin、FFmpeg 及字体环境，不能保证所有字幕都与本地播放器完全一致。

如果视频画面本来就带有字幕，无需再次烧录。读取不到字幕时，应先检查 Jellyfin 中的字幕识别情况；此功能使用 Jellyfin 返回的字幕轨道，不会自动寻找任意外挂文件，也不代表 B 站来源支持相同的字幕烧录流程。

## 为什么要预载？

首次播放一个尚未缓存的 HLS 链接时，可能需要依次等待 Jellyfin 启动转码、生成开头分片，以及云端下载这些分片。开发中观察到，相同链接在已有缓存后重新播放，起播明显更快；预载就是把这段等待提前到观众开始观看之前。

点击预载后，服务器会按视频时长缓存开头的一部分，默认 **5%**，向上取完整分片。例如一段 25 分钟的视频，目标约为开头 75 秒，实际长度取决于分片边界。预载与播放共用同一份缓存，命中的分片可直接向观众发送。

预载适合开场前手动准备，不必先下载整部影片。不过它只改善已缓存部分的等待：跳到未缓存的位置仍需回源，后续播放也要求 NAS 和网络持续跟得上。预载完成后若相关缓存被淘汰，仍可能重新下载；它不是永久保存或完全消除拖动延迟的保证。

## B 站直链已经能播放，为什么还要中转？

**中转是可选的，主要价值是统一取流、共享缓存和管理播放入口。** 如果解析出的直链在所有观众的播放器里都能稳定播放，直接使用它更简单，也不会占用自己的服务器出口带宽。B 站来源本来就不经过自己的 NAS，因此这里的收益不是节省 NAS 上传，而是把多人观看时的取流交给一台可管理的服务器。

- **统一回源与共享缓存**：观众连接中转服务器，由服务器向 B 站 CDN 获取缺失数据。同一媒体的相同缓存块可以复用，减少重复回源；管理员也能统一查看流量、缓存和错误，并按出口 IP 控制带宽。观众到服务器的网络仍各不相同，不能保证所有人的播放体验一致。
- **直接粘贴分享内容**：支持 BV 号、视频页面地址和带标题的分享文字，由服务器解析并检查受支持的 MP4 来源，不必先在个人浏览器里运行解析脚本再复制长直链。
- **处理临时直链失效**：通过 BV 链接创建时，服务保留视频标识，可在源地址即将过期或失效时尝试重新解析，并在确认媒体版本一致后继续使用原中转入口。仅输入解析后的 MP4 直链时，没有对应的视频标识，无法提供同样的自动续期能力；续期也不保证一定成功，媒体版本改变时需重新生成链接。

服务器解析还有一个值得验证的网络因素：解析发生在实际回源的服务器上，而不是观众的电脑上。不过，“不同地区解析一定会拿到不同或更快的 CDN”并不是本项目已经证实的结论。具体地址和速度应以实际解析结果与回源测试为准，不能把服务器解析理解为自动选出最优线路。

中转会增加一跳网络传输，并消耗云服务器的带宽和磁盘。只有服务器到源站、观众到服务器这两段链路都合适，才可能改善体验；服务器线路不好或出口不足时，反而可能更慢。当前 B 站流程针对受支持的单文件 H.264/AAC MP4 做缓存与分发，不负责把所有 B 站视频格式转码，也不能绕过登录、付费或其他访问限制。是否允许共同观看或再分发，仍需遵守内容授权和平台规则，详见[合法使用与合规](#合法使用与合规)。

## 最近创建与最近复制（2.7.0）

放映列表顶部显示最近创建、最近复制链接的标题和时间，点击可定位卡片。列表可按创建时间或名称正倒序排列，最近成功复制的卡片会显示标签及静态柔光边框；复制其他卡片后标记随之切换。

记录保存在服务器缓存卷中，刷新、换浏览器或重启后仍可查看，所有管理员共享。复制不等于实际观看或看完；旧版复制行为无法补回，删除链接也会删除其记录。未填写名称时会尝试使用媒体源名称，建议连续看剧时填写剧名及集数。

从使用 config/.env 布局的 2.5.1 或 2.6.x 更新可使用独立更新包，详见 [UPDATE.md](UPDATE.md)，无需修改现有配置或迁移视频记录。

## OBS 直播（2.9.0）

新增独立“直播管理”视图，与点播和设置共用登录并可直接切换。OBS 使用 RTMP 推流到服务器，VRC 使用 `rtspt://`（RTSP over TCP）观看；默认端口分别为 TCP 1935 和 8554。服务器只转发，OBS 应输出 H.264 / AAC；不录制、不回放、不支持拖动直播进度。

可创建多个直播间，复制推流及播放信息，查看引擎状态、媒体轨道、输入/发送速率、观看 IP 和连接数。直播具备独立动态限速、每出口 IP 10 Mbps 准入预算下限，以及单房间/全局清退暂停、恢复、停用和推流密钥重置。直播预算与点播预算之和必须适合物理出口，不会自动相互借用。

一键脚本自动生成内部鉴权配置并启动固定版本 MediaMTX 容器，保留原点播数据。升级后需额外放行两个 TCP 端口，并使用直连服务器的域名；网站 HTTPS 反向代理配置无需为直播增加 location。详见 [直播部署与使用说明](LIVE.md) 和 [更新说明](UPDATE.md)。

## 批量管理（2.8.0）

创建成功后保留标题输入，便于继续修改集数；来源链接仍清空。放映列表支持创建时间和名称正倒序，名称按自然数字顺序比较，排序偏好保存在当前浏览器。创建时间排序使用链接首次创建时间；顶部的“最近创建”仍表示最近一次生成操作。

“播放与批量管理”内提供四个操作，均需确认：

- 清退所有客户端并暂停播放：断开当前视频连接，拒绝新的视频请求；恢复播放后允许重新连接。
- 恢复播放：重新开放仍有效的播放链接。
- 清空视频缓存：先暂停播放、取消预载，再释放缓存；保留列表、标题和复制记录。
- 清空列表及缓存：同时删除链接及记录，旧链接失效；停止本服务已知的 NAS 转码会话。

暂停状态保存在缓存卷的 `playback.json`，重启后仍保持；清理结束需手动恢复。已下载到播放器的缓冲无法撤回，本服务也不能把玩家踢出 VRChat 房间。清退只针对视频传输，不主动取消预载；两种清理都会取消预载。仍在回源或有缓存被占用时，清理会提示稍后重试并保持暂停，不强删正在使用的文件。

## 功能

- **Jellyfin 点播**：视频可选择重新编码为 H.264 或 HEVC（H.265），音频可转为 AAC；可选分辨率、码率和字幕烧录，也支持保留兼容轨道。
- **原文件缓存**：HTTP Range、暂停、拖动、按需下载及共享 LRU 缓存。
- **B 站来源**：支持 BV 号、视频页面 URL、带标题的分享文字和受支持的 MP4 直链；服务器解析并尝试续期。
- **预载**：手动预载 HLS 开头，默认 5%，与观众播放共用缓存。
- **带宽控制**：总带宽按配置比例使用，按出口 IP 分配，最低接纳带宽 10Mbps/IP；容量不足时拒绝新增 IP，保留已接纳客户端。
- **统一管理页面**：一次登录，视频和设置间直接切换；保留当前页面草稿及标签页登录状态。
- **运行统计**：服务发送/回源流量、系统 CPU/内存、缓存占用、活跃客户端估算和调试日志。
- **NAS 硬件配置**：NVENC、QSV、VA-API、AMF；读取现有 Jellyfin 配置后修改、保存并手动应用。
- **本地轻量界面**：CSS 玻璃效果、SVG 和原生 JavaScript，无远程 CDN、字体或前端构建步骤；支持减少动态效果。

```text
Jellyfin / 受支持的视频来源
           │ 缺失数据按需回源
           ▼
    Relay 共享磁盘缓存
       ├── 观众 A
       ├── 观众 B
       └── 观众 C
```

## 一键部署

准备 Linux 服务器（以 Ubuntu 24.04 为目标环境）、Python 3、Docker Engine 和 Docker Compose 插件。已有 1Panel Docker 可直接使用。建议从 2 核 / 2GB 起步，实际可承载人数取决于码率、出口带宽和回源能力。

下载发布包，解压，进入含 `install.sh` 的目录：

```bash
sudo bash install.sh
```

首次运行只需填写：

1. **公开 HTTPS 地址**，例如 `https://relay.example.com`，可包含自定义端口，不带路径。
2. **Jellyfin 主机名**，例如 `jellyfin.example.com`；多个用逗号分隔，仅使用 B 站可留空。

脚本自动生成高强度管理密钥及 `config/.env`、设置权限、构建并启动容器、等待 Docker 健康检查通过。首次生成的密钥会显示在终端，请妥善保存。**不需要重命名配置文件，也不需要单独执行迁移脚本。**

脚本不会自动安装 Docker、配置 DNS/防火墙、申请证书或更改 1Panel 网站。第一次构建需要获取 `python:3.12-slim` 基础镜像；发布包不包含 Docker 镜像。

非交互安装（把示例域名换成自己的）：

```bash
sudo bash install.sh --non-interactive \
  --public-url https://relay.example.com \
  --jellyfin-host jellyfin.example.com
```

仅生成配置而不启动容器：

```bash
sudo bash install.sh --init-only
```

重复执行会保留现有配置、管理密钥及缓存；首次参数不会覆盖已有配置。旧版根目录 `.env` 会自动迁移到 `config/.env`，原文件保留。已有配置无效时会明确报错，不静默更换密钥。

## HTTPS 与 1Panel

应用只绑定 `127.0.0.1:18080`。使用域名、有效 TLS 证书和 Nginx/1Panel 反向代理公开 HTTPS 入口，示例见 [nginx.example.conf](nginx.example.conf)。默认示例使用 443；更换端口时同步修改 `PUBLIC_BASE_URL`、监听、重定向和防火墙规则。

在 1Panel 建站并配置证书后，将网站代理到 `http://127.0.0.1:18080`，保留 `Range` / `If-Range`，覆盖 `X-Real-IP`，关闭代理缓存、响应缓冲和临时文件。不要重复添加 `location /`，保留证书管理器的 ACME 验证配置。

`/ui.css`、`/ui.js` 和 `/settings-app.js` 也由应用提供，必须能通过代理访问，不能被网站静态扩展名规则拦截到空目录。使用独立桥接网络的 Nginx 容器时，其 `127.0.0.1` 不是宿主机，需根据实际网络调整代理地址及可信代理网段。

```bash
curl http://127.0.0.1:18080/health
curl https://relay.example.com/health
```

成功时返回 `{"ok": true}`。公开地址无法访问但本机健康检查成功时，检查 DNS、TLS、代理及安全组，不要通过暴露 18080 代替 HTTPS。

## 使用

1. 打开公开地址并用管理密钥登录。未登录时不显示视频列表、设置和统计。
2. 添加 Jellyfin `/Items/<影片ID>/Download?api_key=<密钥>` 链接，或受支持的 B 站来源。不要把真实源链接粘贴到公开 Issue。
3. 选择输出参数；“是否重新编码”后可选 H.264 或 HEVC（H.265），取消勾选则保留源视频编码。默认仍为 H.264、1080p、8Mbps，AAC 立体声 192kbps。读取字幕后可选择烧录；烧录需要手动启用重新编码，且保留所选的 H.264 / HEVC。
4. 生成播放链接，按需预载，再复制给播放器。暂停/拖动还需世界播放器支持 HLS 点播及同步。
5. “设置”中调整缓存、带宽、默认转码参数、刷新周期、调试开关及页脚信息，保存到 `.env` 后即时生效。

Jellyfin 硬件加速属于 NAS 全局设置：NAS 必须先安装正确驱动并配置容器设备映射；Relay 不会自动完成这些操作。保存 Relay 配置不会自行修改 NAS，需单独点击应用，这会影响该 Jellyfin 实例其他用户后续的转码。当前集成按 Jellyfin 10.10.7 接口实现。

## 配置

唯一生效的配置文件为 `config/.env`；完整默认项见 [.env.example](.env.example)。

| 配置 | 默认/用途 |
| --- | --- |
| `ADMIN_TOKEN` | 安装时随机生成，管理 API 密钥 |
| `PUBLIC_BASE_URL` | 安装时填写，公开 HTTPS 根地址 |
| `UPSTREAM_HOSTS` | 安装时填写，Jellyfin 来源主机白名单 |
| `CACHE_MAX_BYTES` | 9,000,000,000 字节，可在页面调整 |
| `CHUNK_BYTES` | 2MiB；已有缓存卷不可更改 |
| `BANDWIDTH_TOTAL_MBPS` | 200Mbps，请按实际服务器修改 |
| `BANDWIDTH_UTILIZATION` | 80%，默认有效总上限 160Mbps |
| `BANDWIDTH_CLIENT_MBPS` | 单出口 IP 32Mbps 上限；0 为按接纳数量均分 |
| `REFRESH_SECONDS` | 3 秒 |
| `FOOTER_ICP` | 空；如适用，填写自己实际有效的备案号 |
| `NAS_API_KEY` | 空；仅管理 NAS 全局设置时按需配置 |

页面设置即时持久化；手动更改部署参数后运行 `sudo bash install.sh --non-interactive`。配置、缓存元数据及备份可能包含源链接或密钥，应限制访问。首页登录与设置共用会话；退出登录会清除当前标签页保存的管理密钥。

## 更新、排障与备份

覆盖程序文件并保留 `config/`，在**原项目目录**再次运行：

```bash
sudo bash install.sh
sudo bash compose.sh logs --tail=100 relay mediamtx
```

不要改变 Compose 项目名/目录名，也不要执行 `docker compose down -v`，否则可能创建新卷或删除数据。更新后强制刷新浏览器。如果忘记管理密钥，可在服务器本地查看：

```bash
sudo grep '^ADMIN_TOKEN=' config/.env
```

备份 `config/.env` 和 cache 命名卷。安装脚本不会自动复制整个缓存卷；发布、提交或分享日志前请排除配置、缓存、播放标识、签名 URL 和代理日志。

## 限制与安全边界

- 缓存上限仅针对媒体缓存，Docker 镜像、构建缓存、日志、元数据及 NAS 临时转码文件另计。
- 活跃客户端是访问行为估算，不等于真实观看人数。限速按出口 IP，同一 NAT 下的多位观众共用额度。
- HLS 使用有限 VOD 时间轴和 TS 分片；不支持通用任意 HLS、直播、DRM、独立软字幕及所有播放器格式。HEVC/FLAC 等原格式仍可能存在兼容性问题。
- B 站匿名接口、清晰度、分离音视频形式及签名直链可能变化；不承诺所有视频可用。不能把浏览器能播放理解为具备再分发授权。
- 播放链接是持有即可访问的随机地址；管理密钥保护管理 API，不会让公开播放地址自动变成逐观众授权。停止回源会话不撤销播放链接，撤销访问需删除相应链接。
- 调试会排除部分敏感字段，但仍应人工检查导出内容。程序内存会处理 IP / User-Agent 等请求信息以限速和估算统计，代理也可能另行记录日志。
- 不包含自动内容审核、完整投诉处理平台或运营资质检查，不适合未经额外设计就开放为公众上传/解析平台。
